## Sovereign Process Architecture (SPA): the methodology

SPA is a domain-agnostic specification grammar built on four architectural invariants:

- **Provenance-First Verification**: no inference enters the reasoning chain without a traceable source
- **Gate-Ordered Reasoning**: later gates cannot bypass earlier requirements; sequence is enforced architecturally
- **Longitudinal Window-Based Truth**: truth is a governed trajectory, not a snapshot
- **Deterministic Validation with Prohibited Content Enforcement**: specific outputs are structurally blocked at the architecture level, not the policy level

SPA-derived systems are specified to produce an **immutable Flight Recorder**, a SHA-256 hash-chained audit trail, so that each reasoning chain can be reproduced, traced and defended. Where a system's implementation does not yet meet that specification, its status below says so.

### Domain specifications and status

Each domain is a specification in the SPA grammar, with provenance discipline throughout. Status describes what exists today. **Specification** means a written architecture that has not been calibrated or deployed. **Demo** means it has been shown to an audience using real or synthetic data. **Production** means it is running for real users. No specification is authorized for operational use before domain calibration is complete.
